# sq-05: Claude Code CLI file discovery validation

**Question**: Does the Claude Code CLI discover and respect AGENTS.md on its own, independent of
CLAUDE.md?

**Methodology**: Run `claude -p --model haiku` (CLI v2.1.258) with a trivial prompt ("Reply with the single word OK
and nothing else.") in test directories containing different combinations of AGENTS.md and
CLAUDE.md files, each with a unique canary word that should appear in the output only if the file
was read. Canary file text was e.g. "In every reply, include the word PINEAPPLE somewhere." Each test was a single run (n=1) — null results should be read with that in mind.
Independent verification: the parent agent re-ran Test A (AGENTS.md only) and got bare "OK", confirming the null. During Opus review, AGENTS.md-only was re-run with a LYCHEE canary (bare "OK"), a symlink CLAUDE.md -> AGENTS.md honored a GUAVA canary 3/3, and parent-dir CLAUDE.md discovery was confirmed with a PAPAYA canary.

## Test Results

| Test | Setup | Canary | Expected Output | Actual Output | Verdict |
|------|-------|--------|-----------------|---------------|---------|
| A | AGENTS.md only (contains "PINEAPPLE") | PINEAPPLE | OK PINEAPPLE | OK | **FAIL** |
| B | CLAUDE.md only (contains "MANGO") | MANGO | OK MANGO | OK MANGO | **PASS** |
| C | Both files (AGENTS.md has PINEAPPLE, CLAUDE.md has MANGO + "never include PINEAPPLE") | MANGO (suppression confound) | OK MANGO | OK MANGO | **INCONCLUSIVE** — CLAUDE.md's "never include PINEAPPLE" clause means this output is consistent with both "AGENTS.md ignored" and "AGENTS.md read but canary suppressed". Verdict carried by A and D. |
| D | Parent dir contains AGENTS.md with PINEAPPLE, run from child dir | PINEAPPLE | OK PINEAPPLE | OK | **FAIL** |
| E | CLI documentation check | — | CLI mentions AGENTS.md discovery | Not found; `--bare` mentions "CLAUDE.md auto-discovery" | **NO EVIDENCE** — absence from `--help` is weak evidence on its own; consistent with A/D. |

## Analysis

### Discovery Mechanism

The Claude Code CLI **does not discover or respect AGENTS.md at all**. Based on:

1. **Test A**: AGENTS.md alone has zero effect on CLI behavior.
2. **Test B**: CLAUDE.md alone is consistently honored.
3. **Test C**: When both exist, CLAUDE.md is followed. Test C is confounded (see table) and cannot distinguish "AGENTS.md ignored" from "AGENTS.md read but canary suppressed" — the ignore verdict rests on A and D.
4. **Test D**: Parent directory AGENTS.md is not discovered. This says nothing about CLAUDE.md: parent-directory **CLAUDE.md** *is* discovered (verified separately during review with a PAPAYA canary in the parent dir, run from the child).
5. **Test E**: The CLI help explicitly mentions "CLAUDE.md auto-discovery" (in the `--bare` flag
   description) but never mentions AGENTS.md.

### File Search Order

The CLI discovers instructions exclusively from **CLAUDE.md**: the working directory's file, plus parent directories' CLAUDE.md files (parent discovery verified with a PAPAYA canary during review). It does not look for AGENTS.md at all.

### Precedence (when both exist)

When AGENTS.md and CLAUDE.md both exist in the same directory, CLAUDE.md wins because AGENTS.md
is never loaded; there is no conflict resolution — AGENTS.md is simply ignored.

## Verdict

**TWO-FILE** (fallback)

The claim that "AGENTS.md alone could replace both files" is **false**. The CLI architecture is
hard-wired to discover only CLAUDE.md, not AGENTS.md. The two files serve different purposes:

- **AGENTS.md**: Agent orchestration protocol — human-readable; describes how to organize
  multi-agent work within the project. Not picked up by the CLI.
- **CLAUDE.md**: Repo conventions for Claude Code CLI. Auto-discovered by `claude` command and
  injected into system prompts.

### Recommended approach

Keep both files and add an explicit protocol section to AGENTS.md stating:

- AGENTS.md is the single source of truth for agent orchestration and repo structure.
- CLAUDE.md is auto-discovered by the Claude Code CLI and contains repo conventions.
- The two files are deliberately disjoint. Keep the shared topics (branch/worktree etiquette, commit style) in sync in both directions; everything else lives in exactly one file.
- Do not replace CLAUDE.md with a symlink to AGENTS.md: a symlink technically works (verified 3/3 — the CLI opens the `CLAUDE.md` path and the filesystem resolves the link), but it would force two intentionally different documents into one.

This maintains clear semantics and avoids false optimization attempts.
