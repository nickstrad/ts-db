# lx-04: k6 load-shape breaking knee

## Result

The first visible degradation was request latency, not HTTP errors. For comparison, this report uses **p99 above 500 ms** as an exploratory degradation marker; the first 30 seconds of the ramp at 10 VUs measured 294 ms p99. Every run completed with a 0% `http_req_failed` rate and no failed checks.

| Shape | First-degrading metric and value | Whole-run p50 / p99 | HTTP error rate | Throughput |
| --- | --- | --- | --- | --- |
| Ramp: 10 → 50 → 100 → 200 → 300 VUs | p99 crossed 500 ms in the 30–60 s bucket: **524 ms** at an average 18 VUs and 73.3 req/s. At 300 VUs, p99 reached 6.69 s while throughput was about 61 req/s. | 1.16 s / 6.69 s | 0% (0/21,954) | 64.91 req/s (21,954 requests) |
| Spike: 10 VUs → 300 over 30 s → 10 VUs | p99 first exceeded 500 ms in the first spike bucket (60–90 s): **3.96 s** at an average 135 VUs and 76.0 req/s. It peaked at 12.86 s during ramp-down/recovery (120–150 s). | 181 ms / 11.06 s | 0% (0/10,659) | 69.94 req/s (10,659 requests) |
| Sustained: 100 VUs for 5 min | The run started beyond the marker: **2.85 s p99** in its first 30 s at an average 93 VUs and 67.7 req/s. Across the five-minute run p99 was 2.32 s. | 1.72 s / 2.32 s | 0% (0/21,230) | 69.76 req/s (21,230 requests) |

The ramp's initial 10-VU bucket measured p50 157 ms, p99 294 ms, and 68.4 req/s. The following 30-second buckets rose to p99 864 ms at an average 38 VUs, then 1.46 s at 60 VUs and 1.85 s at 85 VUs. Throughput peaked at 79.5 req/s in the 60–90 s bucket and then stayed around 60–70 req/s as VUs climbed, indicating the server was no longer keeping latency flat as concurrency increased. No HTTP requests failed in any 30-second bucket.

## Method

The local server was started by `deno task serve` on a dynamically selected `127.0.0.1` port, with `BIND_HOST=127.0.0.1` and a fresh `/tmp/lx-04-k6.*` `DATA_DIR` for each run. The runner waited for `/health`, sent k6 traffic to that loopback address, then sent SIGTERM to the server process group and removed the scratch directory. The three run artifacts were retained under ignored `logs/k6/` for this analysis.

The scratch workload reuses item 14's scenario helpers and endpoint mix: 80% reads, distributed 4:2:2:1 across `getGame`, `listGames`, `moveHistory`, and `winsByMark`; 20% writes that advance a VU-owned game or create one when it is complete. Each run seeded 30 games. The executor is `ramping-vus`, so VUs are closed-loop clients; request rate is an observed result, not a fixed offered rate.

Summary p50/p99 values come from k6's exported `http_req_duration` trend. Per-window p50/p99 and throughput were calculated from `raw.json` in 30-second buckets. Throughput is HTTP requests per second. The ramp and spike runs had no dropped iterations; the spike had five interrupted iterations during graceful ramp-down. There were no failed checks or HTTP errors. Results are specific to this droplet, local loopback, and this workload; they are not a production capacity claim.

## Reproduction

The exact runner commands used were:

```bash
PATH="$HOME/.deno/bin:$PATH" bash work-scripts/bash/luna-k6-shape-run.sh ramp lx-04-ramp-20261011
PATH="$HOME/.deno/bin:$PATH" bash work-scripts/bash/luna-k6-shape-run.sh spike lx-04-spike-20261011
PATH="$HOME/.deno/bin:$PATH" bash work-scripts/bash/luna-k6-shape-run.sh sustained lx-04-sustained-20261011
```

The runner's exact k6 invocation was:

```bash
BASE_URL="http://127.0.0.1:$port" SHAPE="$shape" K6_RUN_ID="$run_id" \
  k6 run --out "json=logs/k6/$run_id/raw.json" \
  --summary-export="logs/k6/$run_id/k6-summary.json" \
  work-scripts/deno/k6-load-shapes.js
```

`shape` is `ramp`, `spike`, or `sustained`. The script defines the VU stages and requests p(50), p(90), p(95), and p(99) trend statistics. The runner and scenario are retained in `work-scripts/bash/luna-k6-shape-run.sh` and `work-scripts/deno/k6-load-shapes.js`.

## Implication for item 25

On this host and mix, p99 latency is the useful early warning: it crosses 500 ms well before HTTP errors appear, and the 100-VU sustained run operates around 70 req/s with 2.32 s p99. Item 25 can use this as a local comparison point, but should set its perf envelope from latency objectives and repeat the shape on its intended test host; the observed closed-loop VU counts do not translate directly to arrival-rate capacity.
